# Versión de DKOps usada por los cuatro casos de uso del TFM.
# Se fija un tag concreto, nunca "main", para que el proyecto sea reproducible.
#
# Instalación:
#   pip install "dkops[local] @ git+https://github.com/brrsanchezfi/DKOps.git@v0.3.4"
#
# El extra [local] añade pyspark 3.5.3 y delta-spark 3.2.0 para desarrollo y
# tests offline. En Databricks NO se instala ese extra: pyspark lo aporta el
# runtime del cluster, y la única dependencia real de DKOps es loguru.
#
# Histórico:
#   v0.3.0 — primera versión usada en el TFM. Tres limitaciones detectadas
#            durante la implementación y reportadas como incidencias:
#            el wheel se identificaba como 0.2.4, la promoción a Silver no
#            generaba _silver_created_at, y los comentarios del contrato solo
#            llegaban a Unity Catalog si la tabla la creaba CreateWriter.
#   v0.3.1 — las tres corregidas. Añade `apply_contract_metadata()`,
#            idempotente, que permite documentar tablas ya creadas sin
#            recrearlas, y `insert_only_columns` en el upsert, para que
#            _silver_created_at no se sobrescriba en cada MERGE.
#            No llegó a usarse: introdujo una regresión de empaquetado que
#            impedía instalarla en Databricks (`license = "MIT"` en formato
#            PEP 639 exige setuptools>=77, pero build-system pedía >=68).
#   v0.3.2 — corrige esa regresión. Verificado construyendo con setuptools
#            68.0.0, que es la versión con la que fallaba.
#   v0.3.3 — el contrato gobierna la escritura por cualquier camino:
#            `_write_df` y `_write_stream` respetan `type: EXTERNAL` y
#            `location` en vez de crear la tabla MANAGED desde el esquema del
#            DataFrame, `AppendWriter` aplica la metadata del contrato, y
#            `cdc_merge` garantiza que `is_deleted` llegue a Silver como true
#            o false, nunca NULL.
#   v0.3.4 — el registro operativo anota los cierres. `started_at` pasa a
#            nullable y el logger lo recuerda por `run_id` para repetirlo en la
#            fila de cierre, de modo que la duración sale de una resta y no de
#            un self-join. El `except` que envolvía la escritura pasa de
#            `warning` a `error` con el tipo de excepción: es lo que convirtió
#            el fallo en invisible durante 25 ejecuciones.

v0.3.4
